# Final_project

Итоговый проект курса «Инженер по тестированию: автоматизация на Java».
UI-автотесты для сервиса «Доска объявлений»: https://qa-desk.education-services.ru/

Автор: Valerie Mikhnenko

## Что проверяется

- регистрация с новым email;
- повторная регистрация с уже занятым email;
- вход зарегистрированного пользователя;
- создание объявления;
- редактирование своего объявления;
- удаление своего объявления.

## Технологии

Java 11, Maven, Selenide, Cucumber, JUnit 5, PicoContainer, RestAssured, Allure.

## Структура

- `features` — сценарии на Gherkin (`src/test/resources/features`)
- `steps` — реализация шагов
- `pages` — Page Object
- `api` — запросы к API для подготовки данных (регистрация пользователя, создание и удаление объявлений)
- `data` — генерация тестовых данных
- `context` — общие данные сценария, передаются в шаги через PicoContainer
- `hooks` — настройка браузера перед тестом и удаление объявлений после
- `runners` — запуск тестов

Пользователь для каждого сценария создаётся через API, поэтому тесты не зависят друг от друга.

## Запуск

```bash
mvn clean test
```

Без открытия браузера:

```bash
mvn clean test -Dselenide.headless=true
```

Только один набор сценариев (`@registration`, `@authorization`, `@listings`):

```bash
mvn clean test -Dcucumber.filter.tags="@listings"
```

## Отчёт Allure

```bash
allure serve target/allure-results
```

## Что заметила при исследовании сайта

- После регистрации пользователь сразу авторизован.
- При повторной регистрации под полем email появляется текст «Ошибка».
- Страница объявления заполняется, только если открыть её из ленты на главной. Из профиля и после обновления страницы она пустая.
- Объявление может оказаться не на первой странице ленты, поэтому в тесте удаления лента листается.
- Поиск с кнопкой «Применить» всегда добавляет фильтры «Авто» и «Москва».
- После удаления лента на главной не обновляется, поэтому результат проверяется в профиле и через API.
- В форме редактирования категория и город не подставляются из объявления.
